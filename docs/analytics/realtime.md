# Live visitor report

The authenticated `GET /api/v1/sites/{siteId}/analytics/realtime` endpoint returns recent active visits directly from `raw_event`, before the five-minute aggregate refresh. It accepts `windowMinutes` (1–60, default 30) and `limit` (1–100, default 100). A visit is active when the server received an event for that site-scoped visitor/session pair within the selected window. Response rows include the visit's retained page/event counts, entry and latest page, normalized browser/device/location context, and up to 20 most recent actions.

The site Live tab polls every 10 seconds, offers 5-, 15-, and 30-minute windows, and expands each visit into its recent action trail. It does not apply a saved segment or the dashboard date picker: live membership uses raw receive time, while saved-segment evaluation depends on the session fact pipeline. The view can display IP, TLS fingerprint groups, or browser fingerprint groups. Fingerprint group labels are generated for the current result and never expose fingerprint keys.

Accepted events retain the numeric client IP under a 30-day policy, cleared by the daily retention job. Direct connections use the socket peer address. Forwarding headers are considered only when the immediate peer matches `SEERAY_GEO_TRUSTED_PROXY_CIDRS`; SeeRay reads `CF-Connecting-IP` or `X-Real-IP` and does not trust arbitrary `X-Forwarded-For` values. Events from consent-required sites collected through the JavaScript-free pixel do not retain IP. Old records are not backfilled.

The optional related-visits switch groups records that share the selected signal or anonymous browser ID. This is a display hint only; it does not change visitor counts, identity links, or account records. IP matches can reflect shared networks, and TLS fingerprints are commonly shared by many clients.

The event consumer flushes accepted messages on a one-second schedule, so visibility is near-real-time rather than a delivery-time guarantee. The list is capped at the latest 100 active visits, and action history is limited to the most recent 20 persisted events per visit. Tracker installation and a healthy broker/database pipeline are required for activity to appear.
